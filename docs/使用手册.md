## 第一次使用

### 启动程序

**桌面版**：双击桌面上的「中直高校采购需求审查系统」图标。

**绿色版/源码版**：双击项目目录下的 `启动.bat`，浏览器会自动打开界面。

> 首次启动需要初始化，约 10-30 秒。看到界面即表示启动成功。

### 配置模型（必须做一次）

系统本身不含大模型，需要接入一个模型 API。**只需配置一次**。

1. 点击左侧 **系统设置**
2. 在「模型接入」区域，从下拉框选择一个供应商（推荐 DeepSeek，中文强、价格低）
3. 填写 **API Key**
   - 到供应商官网注册账号并创建 API Key
   - 例如 DeepSeek：登录 platform.deepseek.com → API keys → 创建
4. 点击 **测试连接**
   - 显示绿色「连接成功」→ 配置正确
   - 显示红色「连接失败」→ 按提示排查（多数是 API Key 填错或没有余额）
5. 点击 **设为审查模型**（按钮变成「★ 当前审查模型」）
6. 点击底部 **保存全部设置**

配置完成后，左侧边栏底部会显示绿色的当前模型名称。

> 💡 **没有 API Key 怎么办**：如果单位有本地部署的模型（如 Ollama、vLLM），
> 选择「自定义」，接口地址填 `http://本机IP:端口/v1`，API Key 随意填，模型名填部署的模型名。
> 数据不出内网，更安全。

## 审查一份采购需求文件

### 第一步：上传文件

点击左侧 **审查工作台** → 点击虚线框选择文件，或直接把文件拖进去。

支持格式：**Word（.docx）**、PDF、纯文本（.txt / .md）

> ⚠️ **PDF 必须是文字版**。扫描件（图片型 PDF）提取不到文字，
> 系统会提示，请先用 OCR 转换或改用 Word。

上传后系统会自动解析，并显示识别到的章节，例如：

```
项目概况 | 采购需求 | 技术参数 | 资格条件 | 商务要求 | 评分办法
```

> 如果章节识别不对，会影响审查定位精度。可以在原文件里把章节标题写得更规范
> （如「二、技术参数要求」），重新上传。

### 第二步：开始审查

点击 **开始审查**。系统会：

1. 根据文档内容，从规则库中筛选出适用的规则（通常 40-70 条）
2. 对每条规则：从知识库检索相关法规条文 → 调用大模型判断 → 输出结构化结论
3. 实时显示进度

**耗时参考**：

| 规则数 | 并发数 | 大致耗时 |
|-------|-------|---------|
| 50 条 | 4 | 3-6 分钟 |
| 67 条 | 4 | 5-8 分钟 |
| 67 条 | 8 | 3-5 分钟 |

> 并发数在「系统设置 → 审查参数」里调。调太高可能触发接口限流，
> 建议 4-8 之间。审查期间可以去做别的事，不用盯着。

## 看懂审查结论

### 总体判定

审查完成后，顶部会显示一个彩色横幅：

| 判定 | 含义 | 建议动作 |
|------|------|---------|
| 🔴 **不通过** | 存在严重违规问题 | **不得直接发布**，必须整改后重新审查 |
| 🟠 **需整改** | 存在高风险问题 | 建议整改后再进入采购程序 |
| 🟡 **基本合格（有改进项）** | 无严重问题，有改进空间 | 可酌情采纳建议 |
| 🟢 **通过** | 未发现合规性问题 | 可进入下一环节 |

### 问题分级

| 级别 | 含义 |
|------|------|
| **严重（必须整改）** | 违反法律法规强制性规定，不改会构成违法，可能引发质疑投诉 |
| **高** | 明显不合规或存在较大风险，强烈建议整改 |
| **中** | 不够规范，建议完善 |
| **低** | 细节优化建议 |

### 每条意见包含什么

点击任意一条意见可展开，包含七个部分：

| 字段 | 说明 |
|------|------|
| **问题说明** | 哪里有问题、为什么违反规定 |
| **原文摘录** | 从你的文件里**逐字复制**的问题原文 |
| **法规依据** | 违反了哪一条法规 |
| **知识库检索依据** | 系统实际检索到的法规条文（可点 ↗ 查看原文出处） |
| **整改建议** | 具体怎么改 |
| **建议修改为** | **可直接套用的替换文本** |
| **置信度** | 模型对这个判断的把握程度 |

> ⚠️ **置信度低于 60% 的会标记「建议复核」**。
> 这表示信息不足或模型不确定，请人工确认后再采纳。
> 这类问题通常是因为文件里缺少必要信息（如没附进口产品论证材料）。

### 筛选与批量操作

意见列表上方有筛选标签：全部 / 已勾选 / 严重 / 高 / 中 / 低 / 待复核

右侧按钮：
- **全选** —— 勾选全部问题
- **选严重** —— 只勾选严重级别
- **清空** —— 取消全部勾选

## 自动修订文件

### 操作步骤

1. 在意见列表中**勾选**你要采纳的意见
   （系统默认已勾选「严重」和「高」级别的）
2. 点击 **预览修订** —— 先看看系统准备怎么改
   - 显示每一条将「替换原文」还是「新增条款」
   - 会提示有几条需要人工处理
3. 确认无误后，点击 **生成修订版文件**
4. 点击 **⬇ 下载修订版** 保存到电脑

### 修订版文件里有什么

| 标记 | 含义 |
|------|------|
| 🟡 **黄色高亮** | 已被替换的内容 |
| 🟢 **绿色高亮** | 新增的条款 |
| 📋 **文末表格** | 「修订说明表」，逐条列明改了什么、依据是什么 |

> **原文件不会被修改**，修订版是另存的新文件，文件名带 `_已修订_时间戳`。

### 有些问题没法自动改？

以下情况系统会列入「修订说明表」等你人工处理，**不会静默丢弃**：

- 模型摘录的原文与文件实际文字有出入，定位不到
- 模型没给出可直接套用的替换文本

修订完成后界面会列出这些项目，按说明手动改即可。

### 导出审查报告

点击 **导出审查报告（Word）** 或 **（Markdown）**，
生成一份完整的审查报告文档，可直接用于内部审批留档。

## 管理知识库

左侧 **知识库** 页面。

### 知识库的作用

知识库存放法规文件。审查时系统会从中检索相关条文，作为判断依据。

**知识库越全，审查越准、依据越可靠。**

### 当前内容

系统已内置 **36 部法规全文**，约 91 万字，包括：

- 政府采购法及实施条例
- 政府采购需求管理办法（财库〔2021〕22号）
- 87号令、74号令、110号令
- 中小企业促进办法、进口产品管理办法
- 节能环保品目清单、政府采购品目分类目录
- 台式机/笔记本/服务器等需求标准

### 添加法规

**方式一：上传文件**（推荐）

「添加法规」标签页 → 选择文件（支持 docx / pdf / txt / md）→
填写法规名称、文号 → 点击「入库并重建索引」

**方式二：从网址抓取**

「添加法规」标签页下方 → 粘贴法规页面网址 → 点击「抓取并入库」

> 政府网站部分页面是动态加载的，抓取可能失败。失败时请手动下载文件后上传。

### 自动更新

「更新来源」标签页列出了内置的 9 个权威法规来源。

- **检查来源** —— 验证这些网址是否可访问
- **立即更新** —— 抓取正文，与本地比对，**有变化才更新**
- 后台会按「系统设置」里设定的间隔自动检查（默认 24 小时）

「更新日志」标签页可查看历次更新的记录。

### 检索测试

「检索测试」标签页可以测试知识库能否准确命中法规。

试试输入：
- `以不合理条件限制供应商`
- `投标保证金 2%`
- `财库〔2021〕22号`
- `价格分权重`

会显示命中的法规片段、综合得分（向量得分 + 关键词得分）。

> 这个功能用来验证知识库质量。如果查不到相关法规，
> 说明该法规还没入库，需要补充。

## 常见问题

### 提示「尚未配置审查模型」

到「系统设置」完成模型配置，见[第一次使用](#第一次使用)。

### 测试连接失败

按错误提示排查：

| 提示 | 原因 | 解决 |
|------|------|------|
| 认证失败（401） | API Key 错误或过期 | 重新复制 API Key |
| 接口不存在（404） | 接口地址填错 | 检查 base_url 是否含 `/v1` |
| 触发限流（429） | 请求太频繁 | 降低并发数，或稍后重试 |
| 无法连接模型服务 | 网络问题或本地模型没启动 | 检查网络；本地模型确认服务已运行 |

### 审查很慢

1. 提高「系统设置 → 审查参数 → 并发审查数」到 8
2. 换用更快的模型（如 DeepSeek 比 GPT-4o 快且便宜）
3. 减少规则数：在「审查规则」页确认是否有不适用的规则

### 有些规则没跑（显示执行异常）

通常是模型接口波动。报告里会列出哪些规则异常，
可以重新审查一次，或换模型重试。

### 审查结果不见了

审查结果保存在内存中，**关闭程序后会清空**。
但已导出的报告和修订版文件保留在 `data/exports/` 目录，不会丢失。

> 建议：审查完及时导出报告。

### PDF 上传后提示「未能提取到文本」

这是扫描件（图片型 PDF）。解决方式：
1. 用 OCR 软件（如 Adobe Acrobat、ABBYY）转换为可搜索 PDF
2. 或直接用 Word 版本

### 自动修订提示「仅支持 .docx」

PDF 和 txt 无法回写格式。请把文件另存为 `.docx` 后重新上传。

### 想改审查规则

规则文件在 `knowledge/rules/rules.yaml`，用记事本即可编辑。
改完在「审查规则」页面点击 **重载规则库**，无需重启程序。

规则格式说明见 [README.md](../README.md#审查规则库)。

### 数据会上传到网上吗

- 所有文件、配置、审查结果都**保存在本机**
- API Key 只存在 `data/config.json`，不会上传任何服务器
- 调用模型时，只有**待审查文档内容**和**检索到的法规条文**会发送给你配置的模型服务商

> 如果对数据外发敏感，请使用本地部署的模型（Ollama / vLLM）。

## 重要提醒

⚠️ **本系统是辅助工具，不能替代人工判断。**

- 审查结论基于公开法规和通用规则，**不构成法律意见**
- 模型判断存在不确定性，低置信度项已标记「建议复核」
- 采购需求文件的最终合规性由**采购人及其主管部门**负责
- 请结合本单位适用的内部管理制度和上级规定，对审查结论进行人工确认
